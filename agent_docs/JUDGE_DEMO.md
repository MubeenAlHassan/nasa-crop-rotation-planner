# Field Shift: 180-second judge demonstration

This is a decision-support demonstration for one authorized Faisalabad farm. Use the production backend `app.main:app` with `ENABLE_DEMO_FIXTURES=true` and `BACKEND_DATA_DIR` pointed at this repository root, then the frontend same-origin route `/api/recommend-rotation`. The release manifest is `backend/tests/fixtures/manifest.json`, fixture ID `faisalabad_2025`, catalog version `1.0.1`, transform version `features-v1`, and `synthetic=false`. The POWER archive is genuinely captured; the pinned SoilGrids and SMAP archives honestly record unavailability. Do not substitute the synthetic mock API for this journey.

## 00:00–00:30 — Select the field

Click **Use pinned Faisalabad demo**. The map selects WGS84 latitude `31.4504`, longitude `73.1350`, matching `RecommendationRequest.location` and the manifest `location`. Show that the map still accepts typed coordinates when a tile fails; a failed tile does not change provider data. Moving even slightly away from this point cancels the active request and disarms fixture selection. An arbitrary point must use `data_mode=auto` and cannot receive the pinned observations.

## 00:30–01:05 — Enter history and the dated Rabi slot

Set assessment date `2025-10-15` (`RecommendationRequest.assessment_end`). Add completed **maize** history, `2025-05-01` through `2025-09-30`, with retained residue (`crop_history[0]`). Enter slot ID `rabi_2025`, start `2025-11-01`, end `2026-03-31` (`slots[0]`). Keep rainfed irrigation. Select **Authorized demo fixture** and submit. The browser POST goes to `/api/recommend-rotation`, which forwards contract JSON to `/api/v1/recommend-rotation`; the backend accepts fixture mode only for the pinned farm and period. The crop catalog comes from `GET /api/recommend-rotation?region_id=punjab_pk_demo_v1` and is the cited regional registry, not an invented crop list.

## 01:05–01:45 — Read observed climate and provenance

Point to the **Climate observations and historical stress scenarios** panel. Read rainfall and temperature anomaly values from the returned `features.climate.rainfall_anomaly_pct` and `features.climate.temperature_anomaly_c`; do not recite a fixed number if the returned value is null. Explain that `features.climate.window_start/window_end` covers the prior 90 days and `features.slot_scenarios[0]` is a historical stress scenario for the Rabi slot, not a daily future forecast. Open the `sources` panel: its POWER entry must be `mode=fixture`, `fixture_id=faisalabad_2025`, and refer to the hash-pinned `backend/tests/fixtures/power_archive.json`. NASA POWER combines model/reanalysis and Earth-observation-derived inputs; it is not an in-field sensor. Product reference: [NASA POWER daily API](https://power.larc.nasa.gov/docs/services/api/temporal/daily/).

## 01:45–02:25 — Compare constrained alternatives and explain agronomy

The pinned rainfed submission has `feasible_rotation_count=0`: show the no-feasible-rotation state and `exclusions`, not an invented ranked crop. Chickpea and maize fail the requested planting calendar; wheat requires irrigation. Now change **Irrigation** to **Available** and submit the same point, dates, history, and fixture mode again. This is an explicit farmer-input counterfactual; availability of water has not been independently verified. The returned `recommendations` contains one wheat option. Read its `rank`, `score`, `slots[].crop_name`, and `reasons` from the live response, then show the **Rotation timeline** for its exact dates. Its visible reasons concern water stress and seasonal climate fit; do not claim the engine emitted nitrogen or root-transition reasons in this run. Explain that nitrogen-demand and root-depth transitions are scoring rules that matter only for feasible crop sequences, and point to `components` and `effective_weights` to show which parts of this response actually contributed. The ranking is deterministic under the pinned catalog and rules, but scores are heuristic preferences, not predicted harvest outcomes. Agronomy reference: [FAO crop rotation guidance](https://www.fao.org/4/v9926e/v9926e06.htm).

## 02:25–03:00 — Disclose limits and fallbacks

Show `data_quality`, `warnings`, and all four `sources`. The `DEMO_FIXTURE` warning identifies the pinned capture. This manifest records SoilGrids as unavailable; the soil table must say **Unavailable** for missing axes unless the farmer supplied a separate, dated override. The SMAP Version 6 archive is unavailable because no authorized granules were supplied; the `SMAP_UNAVAILABLE` warning and null `features.moisture.surface_m3_m3` must remain visible. A failed map tile leaves coordinate entry usable. If live data is stale, show `SOURCE_STALE` and the source retrieval time rather than presenting it as current. SoilGrids values are modeled 250 m estimates; SMAP is a coarse surface-moisture product, not a root-zone or field sensor. Product references: [ISRIC SoilGrids documentation](https://docs.isric.org/globaldata/soilgrids/SoilGrids_faqs_01.html) and [NSIDC SMAP SPL3SMP_E Version 6](https://nsidc.org/data/spl3smp_e/versions/6). Close by saying that local validation and farmer judgment remain necessary before planting.
